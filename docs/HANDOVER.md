# Deadweight: handover and progress log

The single document to read before continuing work, in any chat or account.
Last updated at **build 60** (22 Nov 2026). Keep this file current: add to the
build log and move items in "Next" as work lands.

## 1. What this is

**Deadweight** is a shipping-company game in the spirit of *Ports of Call*, built
as an installable offline PWA (Vite + TypeScript, no framework).

- Repository: `beermarkus-tech/Ports` (GitHub). Live: https://beermarkus-tech.github.io/Ports/
- Two eras, each in its own saved game: **Modern** (from 2000, steel and diesel) and
  **Age of Sail** (from 1650, the Dutch: fluyts, monsoons, spice, fog of war).
- The owner plays on desktop and phone and reviews every build by playing it.

## 2. Working rules (the owner's standing instructions)

- **Deploy to main every time.** Develop on the session branch and push both:
  `git push -q origin <session-branch> && git push -q origin HEAD:main`.
  GitHub Actions (`.github/workflows/deploy.yml`) runs `npm test` and `npm run build`
  and publishes to GitHub Pages. Check the run finished green.
- **Report the build number after every deploy.** Build number = `git rev-list --count HEAD`
  (shown in the app header). The deploy workflow fetches full history for it.
- **Proposals first when asked.** When the owner says "make a proposal" or "no
  programming", do not change the app: write the proposal (often as a claude.ai
  Artifact page with mock-ups) and wait for approval.
- **Push back when something seems wrong**; the owner explicitly welcomes it.
- Keep the in-app **reload button** and the **build number**. No "skip to next
  arrival" button. The clock **pauses whenever a ship needs a decision**, and
  restarts by itself after dry dock / waiting / laying up.
- No toasts for arrivals; no bell "ping" on arrivals; sailing ships make a
  sails sound instead of a horn.
- The trade in enslaved people stays out of the game entirely.
- Commit messages end with the attribution lines the harness provides
  (`Co-Authored-By: …` and `Claude-Session: …`). Never put model names in commits or code.
- Write in plain, direct English in the UI. Use UK spellings in game text
  (harbour, colour) as the game already does.

## 3. How to run, test and verify

```
npm install
npm run dev          # local dev server
npm test             # vitest, 118 tests, all must pass
npm run build        # tsc + vite build into dist/
npx vite preview --port 4173 --strictPort   # serve dist/ (base is './', open http://localhost:4173/)
ERA=sail [HOUSE=chinese] npx tsx scripts/balance.ts 10 100 greedy   # balance bots (also: casual)
```

- Browser checks use Playwright (Chromium is preinstalled in the cloud container:
  `require('playwright')`, `chromium.launch()`, contexts with `serviceWorkers: 'block'`).
  Typical script: open `http://localhost:4173/`, click `#games`, start a game with
  `[data-action="slot-new"][data-era="sail"|"modern"]`, then interact.
- Performance: measure with CDP `Emulation.setCPUThrottlingRate {rate: 4}` and either
  long tasks, a timeline trace (`Tracing.start`), or time per step to the next frame
  measured inside the page. Beware: if the ship never leaves port the clock is paused
  and nothing moves, which makes "fast" results meaningless.
- After an era change the app reloads the page (`reloadForEra()` in main.ts).

## 4. Architecture

```

  era.ts        EraConfig: start, currency, calendar, words, rules, fog (charts), trade flag;
                merchant houses of 1650 (HouseConfig: yards, ship list, port names, ship and
                captain names) and CHINESE_HOUSE; eraConfig(era, house)
  world.ts      World per era and house (worldFor(era, house)/setEra(era, house)/getWorld);
                one 1650 data set, each house its own World (yards, port names); Dijkstra routes, one search fills
                routes to all ports; fog-aware (uncharted lanes cost 1.6x)
  game.ts       actions and the clock (advance), voyages, arrivals, books, captains/orders,
                calls on the way (callsOnTheWay, detour, onTheWay, setPlannedDest, ONWAY)
  contracts.ts  boards and pay; economy.ts prices, events; ships.ts values, market, loans
  charts.ts     fog of war (Age of Sail): charted nodes, discovery, charts for sale
  guide.ts      the guide: chapters of steps (conditions on the game), updateGuide marks and reports
  trade.ts      own-account trade and slow news (prices by the latest letter)
  wind.ts       prevailing winds and monsoon; captains.ts; save.ts (slots, migrations)
src/data/  modern world JSON; src/data/sail/ the 1650 world (generated by
           scripts/sail-world.py and scripts/sail-lanes.ts)
src/ui/
  main.ts (in src/) the App: panels, tabs, actions, render loop
  map-gl.ts      world map on WebGL (PixiJS), see section 6 (the only map since build 49)
  map-globe.ts   the optional globe (build 60): sphere shader, 3D lines, view maths
  map.ts         types shared by the map and main.ts (LonLat, PortMarker, ShipMarker, WeatherCell)
  port-scene.ts / port-scene-sail.ts  harbour views (modern / 1650)
  goods-icons.ts drawn icons for all 55 goods (engraved 1650, line-style modern)
  art.ts ship art (incl. junks); music.ts the music engine (Web Audio, all synthesised: lute,
  recorder, viol, pipa, zheng, xiao, wooden fish, gong) and the Dutch sarabande;
  music-nanyang.ts the Chinese house's piece; sound.ts effects (picks the piece per house)
  docking-game.ts, minimap.ts, charts.ts (books), format.ts, update.ts, style.css
tests/     vitest suites (sim, economy, ships, orders, captains, docking, slots,
           sail, fog, trade, jettison, onway)
```

Saves live in localStorage (`deadweight.slots`, `deadweight.save.<id>`,
`deadweight.active`). `save.ts` migrates old saves (v1→v4, new ports, captains,
fog charts, trade samples).

## 6. The WebGL map (build 48; the old map removed in build 49)

**Why:** the current map (section 7) can't zoom like Google Maps. During a gesture
it stretches the SVG layer and redraws the canvas coarsely; on release it redraws
crisply, then re-places names, re-renders fog and swaps in detail. The owner sees
those stages ("blotchy"). Decision: rebuild the map with **PixiJS (WebGL)**, keeping
the Equal Earth projection and both eras' looks. MapLibre was rejected (Mercator,
real-map look, hard to keep fog/night/art). Canvas raster tiles were rejected
(about the same effort, less headroom).

**Principles (the Google Maps way):**
- One renderer draws the complete frame every frame at the exact (fractional) zoom.
  No "stretch now, fix later", no commit phase.
- Geometry (land coarse + detailed, coast lines, graticule, lanes, sphere) is built
  once into GPU meshes in map units (projected with d3-geo `geoEqualEarth`, same
  `fitExtent` as today: W=1000, H=470); zoom/pan only changes the container transform.
- Coarse and detailed coastlines cross-fade by zoom (both resident), no swap.
- Ports, names, ship icons keep screen size (counter-scale per frame; cheap).
- Names: collision placement each frame (42 ports is cheap) with priorities (here,
  destination, cargo ports) and **fade in/out over ~150 ms**, never jump.
- Fog: one high-resolution texture (or blurred mesh) in map units, scaled on the GPU.
- Night shading, weather, routes (animated dashes), wakes, pulses, flashes: drawn
  in the same scene.
- Smooth input: pinch, wheel, drag with inertia; double-tap and buttons animate.
- Accessibility: invisible DOM buttons over ports (focus, Enter, aria-label), since
  the map becomes one canvas. Tapping a port picks the destination; tapping a ship
  selects it; hover highlights routes (desktop).

**Plan (two builds, the current map stays until the new one is at least as good):**
1. New `MapView` on PixiJS behind the same public API (see below): sea with waves,
   graticule, shallows, land (coarse + detailed), lanes (charted only; canals and
   closed canals), ports with names and prices/notes, zoom/pan/gestures, hit testing.
2. Ships (icons, wakes, fan-out in port), routes (primary/glow/secondary), fog with
   its texts, night, weather, pulses and flashes; remove the old SVG/canvas map.
   Re-run the perf checks (zoom steps per frame on a 4x-throttled CPU) and phone layout.

**What build 48 did (`src/ui/map-gl.ts`, class `GlMapView`, same public API):**
- PixiJS 8.22 (pinned). `Application` with `autoStart: false`; our own rAF loop draws only when
  something changed (view, labels fading, state) or, at most ~30 fps, while something animates
  (marching route, ready-ship halo, storms, effects).
- Own shaders on PixiJS `Mesh`es (GLSL without `#version`; Pixi adds the WebGL1/2 defines):
  - line shader: polylines with mitred normals are widened in the vertex shader by
    `uWidth` **screen pixels** (`uPxPerUnit` from a shared `view` uniform group), anti-aliased,
    dashes in screen pixels (`uDash`, `uDashShift` for the marching route). Used for coasts,
    graticule, lanes, canals, rim, routes, wakes.
  - fill shader (earcut triangulation, d3 winding: outer rings turn like the sphere outline):
    land with its top-to-bottom gradient, night (three stacked circles).
  - sea shader: radial gradient, wave marks from a repeating texture at constant screen size,
    and **shallows from a distance field** (distance to land, 2048×964 texture, computed once
    with a Felzenszwalb EDT). Halo width grows with √zoom so it stays smooth up close.
- Land 110m at start; land 50m loads in idle time and cross-fades in between 2x and 2.8x
  (both resident); the distance field is then rebuilt from the detailed coast. Max zoom 12x.
- Fog: the old SVG recipe (blur mask + turbulence) rasterised **once per chart change** into a
  2048-wide texture for the whole world; the GPU scales it.
- Overlay in screen pixels: port dots (Graphics, redrawn only when their look changes), names
  and notes (Pixi Text), ships (from the icon's SVG path), pulses, flash texts, fog names.
  Sizes: names `ui = clamp(s0, 0.8, 1.15)`, dots/ships `dot = clamp(s0, 0.62, 1.15)` where s0 is
  CSS px per map unit. (The old map scaled everything by s0, so names were ~4 px on a phone.)
- Crowded ports (Batavia/Bantam, Canton/Macau…): dots closer than MIN_GAP (12 units) are pushed
  apart at the world view; the push fades out as the zoom separates them (`nudgeShare`). Ships,
  routes, lanes, wakes and effects bend to the pushed dot within NUDGE_REACH (14 units) (line
  shader attribute `aNudge`, `disp()` for points), so a ship arrives exactly on its dot (build 53).
- Names: greedy placement in screen space whenever the view changes: here, destination, stops,
  cargo ports, strike/boom first, then the rest; each takes its current spot, the data's
  spot, then the other spots, the first that's clear of placed names, other dots, the map edge
  the buttons over the map (zoom, Port view) and ships in port, and nearer its own dot than any
  other (build 53). Ports that must show their name (here, destination, stops, cargo) and find no
  spot that reads as theirs (dense clusters at the world view: Amsterdam among London, Bergen,
  Danzig; Amoy on a phone) take one of the same eight spots further out with a leader line to the
  dot, outlined like the names and starting outside a ship in port (build 54). Note line dropped before the name is. No room:
  hidden (important ports always show). Names fade out/in over 150 ms, also when moving spot.
- Input: wheel, pinch, drag with inertia, double-tap / double-click, + − World (eased).
  Taps are hit-tested in JS (ships first, then dots, then names). Hover highlights (desktop).
  Invisible `.map-port-btn` buttons over the dots for keyboard and screen readers.
- GPU portability (build 59, after lines ran to the map's corner on the owner's Android phone):
  never set `mesh.geometry` to a geometry of another size; `swapMesh` builds a new Mesh in the
  old one's place (LineLayer/FillLayer `geometry` setters do this). Vertex attributes are packed
  as vec2/vec4 (aSideDist, aNudge), no float or vec3 attributes. SwiftShader in this container
  does not show such driver bugs: when the owner reports a phone-only glitch, ask for a screenshot.
- The globe (build 60, `map-globe.ts`; Globe/Map button in the zoom tools, choice remembered in
  localStorage `deadweight.mapMode`): orthographic. One shader over a square round the disc finds
  the Earth point under each pixel (inverse rotation), converts it with d3's Equal Earth formula
  (uProj = projection scale and translate) into flat-map units and samples the flat map's
  textures: land mask (canvas fill, 4096 wide, from the coarse then the detailed land), shallows
  distance field, wave tile, fog. Night is computed from the sun vector (three soft bands); limb
  darkening, rim and an atmosphere glow. Lines (coasts from topojson lon/lat rings, cut at the date
  line; graticule; lanes; routes as great-circle arcs; wakes) are 3D polylines (aPos/aPrev/aNext
  vec4, aSideDist vec2), widened on screen in the vertex shader and faded at the rim; same styles
  as the flat map. Overlay positions go through `lonlatScreen`/`portScreen` (flat map: projection +
  push apart; globe: globePoint; z for the far side); names need facing > 0.2, fog names > 0.45;
  ship heading on the globe from the wake. Gestures: drag rotates (with spin after a flick),
  pinch/wheel zoom about the centre, double tap turns that point to the middle and zooms in;
  + − World act on the globe. Clouds move to a screen-space container while the globe shows. No
  dot pushing on the globe. Perf (4x throttled, Playwright): ~2.8 ms JS + 2.9 ms submit a frame,
  as the flat map.
- `window.__map` is the live view, for Playwright checks. Two checks worth re-running after map
  changes (build 54): every port's ship-in-port position equals its dot at 1x/2x/4x/8x in all
  three worlds; and every visible name (without a leader line) is nearer its own dot than any
  other, desktop and phone, at several zooms.
- Measured (4x-throttled CPU, Playwright): ~2.3 ms JS + ~3.1 ms render submission per zoom
  frame. The container renders WebGL in software (SwiftShader), so whole-frame timings there
  are not representative; check on a real phone.

**Status:** the owner played it and approved it ("brilliant"). The old SVG/canvas map and its CSS
were removed in build 49; there is no fallback (the game is for the owner's own device). Without

## 7. The old map (builds 45–48, removed in build 49): lessons kept for reference

(The code is gone; it's in git history before build 49.)
- It was: a `<canvas class="map map-base">` painting sea (radial gradient), wave marks,
  graticule (dotted in 1650), shallows (blurred stroke), land (gradient + coast) and
  lanes via `Path2D` from d3 path strings, aligned with the SVG through
  `svg.getScreenCTM()`. Above it an `<svg class="map map-top">` holds fog (bitmap
  image + texts), night, weather, routes, wakes, ports, ships, effects.
- Zoom state `k, tx, ty` (unzoomed screen units); the SVG's `viewBox` shows the view.
  During a gesture: SVG gets a CSS transform, canvas redraws quickly (coarse coast, no
  shallows), at most once per frame; 160 ms after the last step `commitZoom()` sets the
  viewBox, port/ship counter-scales, crisp canvas; then `afterZoom()` re-places labels,
  re-renders the fog (PNG via `toBlob`) and loads the detailed coast at k ≥ 3.
- Performance lessons learned (keep in mind for the rewrite):
  - Live SVG filters (blur, turbulence) over the whole map are re-rendered every tick:
    rasterise once.
  - A CSS class collision (`.wave`) animated the sea pattern invisibly every frame.
  - Scaling a big SVG group makes the browser process the whole enlarged map;
    a viewBox change culls, but SVG still re-examines huge paths on each tick.
  - Marching-ant dashes on long paths are expensive when zoomed.
